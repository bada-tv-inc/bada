# 작업 지시서: bada / bighug 영상 자동화

> 이 문서만 읽고 바로 작업을 시작할 수 있도록 정리한 지시서입니다.
> 코드 저장소: `github.com/bada-tv-inc/bada`, 브랜치 `claude/youtube-automation-upload-y1o1of`

---

## 1. 목표 (한 줄)

**영상을 폴더에 넣으면 → 터진 영상 공식대로 편집 → 브랜드 템플릿 입혀서 → 유튜브는 비공개 업로드, 인스타 릴스는 파일로 → 사람이 확인한 뒤 공개.**

## 2. 배경

- 관리하는 브랜드는 두 개입니다.
  - **bada** (`bada-tv-inc`)
  - **bighug** (인스타그램 [@bighugorg](https://www.instagram.com/bighugorg))
- 하고 싶은 일
  1. **유튜브 자동 업로드:** 원본 영상을 컷 편집(무음, 다시 찍은 부분, 군말 제거)하고 자막, 제목, 설명, 챕터를 만들어 **비공개로 업로드**합니다. 사람이 확인한 뒤 공개해요.
  2. **릴스 리서치:** 비슷한 계정에서 **조회수 100만 이상**인 릴스를 모아 분석합니다.
  3. **릴스 제작:** 분석해서 나온 공식대로 **우리가 넣은 영상**을 릴스로 만듭니다.
- CapCut은 공식 API가 없어서 자동화에 쓰지 않습니다. 편집은 **ffmpeg**로, 판단(어디를 자를지, 제목, 구성)은 **LLM**이 합니다.

## 3. 입력 자료 (사용자 Mac)

- 외장하드 **Everything**의 `RPD+ Kpop Play Day 2026` 폴더입니다.
  - 경로는 `/Volumes/Everything/RPD+ Kpop Play Day 2026`이고, 없으면 `/Volumes/Everything/Nick/Pictures/RPD+ Kpop Play Day 2026`입니다.
  - 경로에 공백과 `+`가 있으니 따옴표로 감싸야 합니다.
- 안에 있는 것
  - K-pop 행사 영상들. 말보다 음악 위주일 수 있습니다.
  - `Reels_Brand_Kit`: **bada용과 bighug용** 릴스·유튜브 템플릿
- ⚠️ **원본은 절대 수정, 이동, 삭제하지 마세요.** 쓸 영상은 `~/bada_test_output/`로 복사해서 작업합니다.
- 이 경로는 사용자 Mac에만 있어서 **클라우드 환경에서는 접근할 수 없습니다.** 로컬에서 실행해야 합니다.

## 4. 이미 만들어진 것 (브랜치 `claude/youtube-automation-upload-y1o1of`)

```bash
git checkout claude/youtube-automation-upload-y1o1of
pip install -e '.[youtube,reels]'      # ffmpeg 별도 설치 필요 (brew install ffmpeg)
python -m pytest -q tests              # 16개 통과 상태
```

### 4-1. 유튜브: `bada youtube ...` (`src/bada/youtube/`)
| 명령 | 하는 일 |
|---|---|
| `auth --client-secret x.json` | 구글 OAuth를 한 번 연결 |
| `process VIDEO [--no-upload]` | Whisper 받아쓰기 → 무음과 다시 찍은 부분(LLM 판단) 컷 → ffmpeg 렌더 → 자막(SRT) → 제목·설명·태그·챕터(LLM) → **비공개 업로드** |
| `watch FOLDER` | 폴더에 새 영상이 들어오면 자동으로 `process` |
| `publish ID [--at 시간] [--unlisted]` | 확인 끝난 영상을 공개 또는 예약 공개 |
| `status FOLDER` | 처리한 영상 목록과 공개 상태 |

결과물은 `<영상>_bada/` 폴더에 저장됩니다: `transcript.json`, `edits.json`(자른 이유), `captions.srt`, `package.json`, `final.mp4`, `job.json`.

### 4-2. 릴스: `bada reels ...` (`src/bada/reels/`)
| 명령 | 하는 일 |
|---|---|
| `analyze --urls urls.txt --min-views 1000000` | 릴스 분석 (아래 표) |
| `report` | 여러 릴스를 모아 반복되는 공식, 훅 유형, 편집 기법, 리듬을 집계하고 우리 계정용 아이디어를 담은 `REPORT.md` 작성 |
| `make VIDEO [--plan-only] [--plan plan.json]` | 우리 영상으로 릴스 제작 (아래 설명) |

`analyze`가 릴스마다 만드는 것:

| 항목 | 결과물 |
|---|---|
| 원본 화질 다운로드 (yt-dlp, 재인코딩 없음) | `video.mp4`, `info.json` |
| 음성 받아쓰기, 문장 단위 | `transcript.json` |
| 첫 3초를 0.125초마다 원본 해상도로 캡처 (24장) + 모아 보기 이미지 | `hook_frames/`, `sheet.jpg` |
| 컷과 소리 튐(갑자기 커지는 소리, 음 깨짐)을 초 단위로 | `signals.json` |
| 요소별 분석 (LLM이 이미지를 보고 분석): 훅, 구조, 포맷, 편집, 리듬, 오디오, CTA, 공식, 템플릿 | `analysis.json`, `analysis.md` |

`make`는 이렇게 동작합니다.
1. 우리 영상 받아쓰기를 보고 LLM이 공식에 맞춰 구간을 고르고 순서를 바꿉니다. **가장 강한 결과가 맨 앞**에 와요.
2. 1080×1920으로 렌더링합니다.
   - 화면: 풀스크린과 검정 캔버스를 번갈아 사용
   - 효과: Pop 줌, 컷마다 휙 효과음
   - 글자: 한 단어씩 나오는 자막, 헤드라인, 마지막에 댓글 키워드 CTA
3. 결과물은 `<영상>_reel/` 폴더에 저장됩니다: `reel.mp4`, `caption.txt`, `plan.json`.

## 5. 참고 스타일 (사용자가 보여준 분석 예시, @thebranding.ai 조회 234만)

- **구조:** 훅 → 예고 → 패턴 깨기 → 근거 → 정리 → CTA
  - 한 줄 요약: 원본 먼저 → 왜 됐나 질문 → 이유 → 댓글
- **원고 시간 배분**

  | 구간 | 내용 |
  |---|---|
  | 0–3초 | 터진 원본 먼저 재생 |
  | 3–8초 | "광고 0원 → 왜 됐을까?" |
  | 8–24초 | 패턴 깨기 (뇌는 '다른 것'에 반응) |
  | 끝 5초 | 댓글 키워드를 남기면 자료 제공 |

- **포맷:** 터진 원본을 풀스크린으로 먼저 보여주고, 단색 화면에 키네틱 자막으로 해설합니다. 결과를 먼저 보여주고 따라 하게 만드는 방식이에요.
- **편집:** Pop Up, PIP 중앙 30%, 휙 효과음, 검정 캔버스, 한 단어 자막
- **터진 훅 공식 (705편 분석 기준)**
  - 결과를 먼저 틀고 '만드는 법'을 약속하기
  - 인사 없이 첫 항목부터 시작하기
  - '작은 입력, 큰 결과' 격차를 약속하기

## 6. 이번에 할 일 (우선순위 순)

1. **입력 폴더 정리:** 영상(길이, 해상도, 말 위주인지 음악 위주인지)과 템플릿(폰트, 색, 로고, 인트로·아웃트로, CapCut/Premiere 프로젝트, PNG·MOV 오버레이) 목록을 사용자에게 보여주고, 어떤 영상을 쓸지 정합니다.
2. **브랜드 적용:**
   - `brand.yaml`을 만듭니다. 항목은 폰트, 메인색·강조색, 로고와 위치, 인트로·아웃트로, 오버레이예요.
   - `bada reels make`와 `bada youtube process`에 `--brand` 옵션을 추가합니다.
   - bada용과 bighug용을 하나씩 만듭니다.
   - CapCut 같은 프로젝트 파일은 코드로 읽을 수 없으면 폰트, 색, 이미지만 뽑아 비슷하게 맞추고, **어디를 비슷하게 맞췄는지 보고**합니다.
3. **음악 위주 영상 대응:** 말이 거의 없으면 받아쓰기 기반 편집 계획이 동작하지 않습니다. 그 경우에는 아래 방식으로 계획을 짭니다.
   - 화면 전환과 소리가 커지는 지점(`bada.reels.signals`)을 기준으로 가장 신나는 장면을 고릅니다.
   - 가장 강한 장면을 맨 앞에 둡니다.
   - 비트와 피크에 맞춰 컷합니다.
   - 단어 자막 대신 헤드라인을 씁니다.
4. **테스트 제작:** bighug 릴스 1개, bada 릴스 1개, 유튜브 버전 1개를 만듭니다. 릴스는 `--plan-only`로 계획을 먼저 보여주고 확인받은 뒤 렌더링합니다. 유튜브는 `--no-upload`로 파일만 만듭니다.
5. **품질 확인:** 결과물마다 프레임 3~4장을 뽑아 직접 봅니다. 한글 폰트, 자막 가독성, 로고 위치, 잘못 잘린 부분이 없는지 확인하고 문제가 있으면 고쳐서 다시 렌더링합니다.
6. **보고와 커밋:** 결과 파일 경로, 사용한 계획, 사람이 판단할 부분을 보고합니다. **코드만** 같은 브랜치에 커밋하고 push합니다. 영상과 브랜드 자산은 커밋하지 않아요.

## 7. 반드시 지킬 것

- **공개나 게시를 자동으로 하지 않습니다.** 유튜브는 항상 비공개로 올리고, 공개는 사람이 `publish`로 합니다. 인스타는 파일까지만 만듭니다.
- **원본 폴더는 읽기만 합니다.**
- **다른 계정의 릴스:** 분석용으로만 쓰고 다시 올리지 않습니다. 인스타그램 약관상 다운로드는 회색지대예요. 로그인이 필요하면 **관리 중인 @bighugorg 계정이 아닌 별도 계정**의 쿠키(`--cookies-browser`)를 씁니다.
- **API 키나 OAuth 파일을 지어내지 않습니다.** 없으면 사용자에게 묻습니다.
- 테스트(`python -m pytest -q tests`)가 통과하는 상태를 유지합니다.

## 8. 알려진 제약

- **유튜브:** 감사(audit)를 통과하지 않은 API 프로젝트로 올린 영상은 '비공개로 잠김' 상태가 되고, Studio에서도 공개로 바꿀 수 없습니다. 실제로 공개하려면 [API 감사 신청](https://support.google.com/youtube/contact/yt_api_form)이 필요하고 몇 주 걸립니다.
- **유튜브 할당량:** 하루 10,000이고 업로드 1번에 약 1,600을 써서, **하루 6개 정도**가 한도입니다.
- **인스타:** 조회수 100만 이상 릴스를 자동으로 찾는 기능은 없습니다. 스크래핑이 필요하고 계정 정지 위험이 있어서, 릴스 주소는 사람이 골라 `urls.txt`에 넣습니다.
- **아직 실제 데이터로 검증하지 못한 것:** Whisper 받아쓰기, LLM 호출, 실제 업로드와 다운로드. 지금까지는 합성 영상으로 ffmpeg 단계만 검증했습니다.

- 참고할 비슷한 계정과 릴스 주소 목록
- 유튜브 편집을 어디까지 할지. 지금은 컷과 자막만 하고, BGM이나 효과는 없습니다.
